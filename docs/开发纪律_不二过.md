## 〇、流程纪律（每次对话结束必做 · 用户硬性要求）

> 用户要求：**每次对话结束后，自动提取本轮所有开发经验，固化进本文件 + 项目 memory，保证不二过。**

- 每轮对话只要发生代码改动 / 踩坑，结束前必须：
  1. 把新踩的坑写成「错误 N」条目（现象 / 根因 / 对策 三要素齐全）。
  2. 同步追加到项目 memory 的「开发纪律与已知坑」章节（长期复用）。
  3. 跑完下方「交付自检清单」，确认是**真实修复**而非掩盖。
- 没有新坑 → 只更新「已固化的技术事实」，不必硬造条目。
- 这条纪律本身不可跳过：漏做 = 未遵守不二过。

## 二、我犯的 5 个低级错误（核心：必须不二过）

### 错误 1：导航漏改 —— 你根本找不到新功能入口
- **现象**：AI复盘库只加在新建的 `ai_history.html`，漏了 index/replay/realtime/review 四个旧页面，你看了半天导航栏没有入口。
- **根因**：新增全局导航项时，只改了新页面，没用"全局思维"同步所有页面。
- **对策（铁律）**：
  1. 任何**全局导航/样式/组件**变更，必须 **5 个 HTML 页面一起改**。
  2. 改完用 `grep "目标串" *.html` 确认 **5 处都在**，再交付。
  3. 不在对话里说"已加导航"，必须先 `grep` 验证数量。

### 错误 2：数据对比时间戳错开 —— 得出了错误结论
- **现象**：曾断言"下午表格价与实时接口一致"，实际是把表格 16:31 的价拿去比 17:5x 的实时价，时间戳根本不同。正确比价后下午同样偏 5~12 点。
- **根因**：为了"快点给结论"，偷懒用"现在"的价去凑，而不是严格取**信号时刻那根 1m K线**的价。
- **对策（铁律）**：
  1. **比价必须严格取信号时刻对应的 1m K线**（open/high/low/close），绝不用"当前实时价"代替。
  2. 任何"对得上 / 对不上"的结论，**必须跑脚本逐条输出 delta** 给你看，不许口头臆断。
  3. 口头结论前先问自己：时间戳一致吗？数据源是同一个吗？

### 错误 3：过度实现 —— 你只要 100，我做了整套持久化
- **现象**：viewWindow 你明确说"改成 100"，我却自作主张加了 localStorage 持久化 + 回退逻辑，被你打回。
- **根因**：没尊重"最小改动满足字面需求"原则，过度代入了自己的设想。
- **对策（铁律）**：
  1. **字面需求优先**：用户要什么就给什么，先交付最小可用改动。
  2. 想加额外功能（持久化/校验/提示），先说一句"要不要顺带做 X"，**等你确认再动手**。
  3. 把"做得多"当成风险，不是功劳。

### 错误 4：诊断绕路 —— 反复改前端，问题其实在别处
- **现象**：`realtime` 空白反复改前端逻辑，最后发现后端本来正常，是浏览器 fetch / 缓存问题。
- **根因**：没先用铁证锁定问题层（后端 vs 前端），就闷头改代码。
- **对策（铁律）**：
  1. **改前端前先用 curl / urllib 打接口拿铁证**（HTTP 状态码、返回 JSON、data 条数）。
  2. 后端实测正常 → 问题在浏览器侧，重点查 fetch / 缓存 / 状态机，而不是继续改请求逻辑。
  3. 任何"为什么没刷新 / 空白"类问题，第一步永远是**先 curl 接口**。

### 错误 5：手滑误伤 + 脚本路径错 —— 截断函数、找不到文件
- **现象**：Edit 时把 `review_page` 函数体截断过；TestClient 脚本没 `cd` 导致相对路径找不到文件，误报路由失败。
- **根因**：Edit 的 old_string 不够精确（覆盖了函数签名但丢了 body）；脚本偷懒用相对路径。
- **对策（铁律）**：
  1. Edit 的 old_string 必须**完整包含要替换的整段**，改完立即 `py_compile` 验证语法。
  2. 测试脚本一律用**绝对路径**或先 `cd` 到项目目录再跑。
  3. 任何"路由 404 / 文件找不到"先怀疑自己脚本问题，不是代码问题。

### 错误 6：前端调用了未导入的 Vue API → 运行时 ReferenceError 整页白屏
- **现象**：`/ai_history` 详情弹窗点「发送」或回车后，除顶部导航外整页空白（DOM 被清空）。
- **根因**：内联 JS 用了 `nextTick(autoScrollChat)` 做滚动，但解构行只写了 `const { createApp, ref, computed, onMounted } = Vue`，**漏了 `nextTick`**。运行到 `askAIHistory` 时抛 `ReferenceError: nextTick is not defined`，Vue 渲染崩溃 → 白屏。
- **对策（铁律）**：
  1. 前端写完后，**列出 setup 里用到的全部 Vue API**（createApp/ref/reactive/computed/watch/onMounted/onUnmounted/nextTick…），逐一对照解构声明行，缺一个补一个。
  2. 更省心做法：解构行**一次性全量导入常用 API**，杜绝漏写：
     `const { createApp, ref, reactive, computed, watch, onMounted, onUnmounted, nextTick } = Vue`
  3. 白屏类问题第一反应：开浏览器 **Console 看红色报错**（多半是 `ReferenceError`/`TypeError`），别瞎改 DOM。
  4. `node --check` **只能查语法，查不出"未定义变量"这类运行时错误**——必须靠解构对照 + 浏览器实测兜底。

### 错误 7：多轮对话连发两个白屏 bug —— 写完没在真实浏览器跑（2026-08-27）
- **现象**：大模型多轮对话功能（/review 生成后追问 + /ai_history 详情继续追问）交付后，你一发送就白屏。先后暴露两个独立根因：
  1. `ai_history.html` 漏导入 `nextTick` → 运行时 `ReferenceError` 整页白屏（与错误 6 同机制）。
  2. `main.py` 两处 SSE 队列 `asyncio.Queue(maxsize=64)`，AI 长报告产出快于前端消费 → `put_nowait` 抛 `QueueFull` → 流崩溃、收不全 → 白屏/卡死。
- **根因（核心）**：我验证时只跑了 `py_compile` + `node --check` + TestClient，**从没在真实浏览器里点一次"发送"**。两个 bug 都是纯运行时错误（未定义变量、队列打满），语法检查与单测根本查不出。
- **更深的低级性（必须承认）**：
  - `nextTick` 漏写是手误，本该写前端时逐行核对 Vue API 解构（错误 6 已立铁律，但**新页面没复用**）。
  - `maxsize=64` 是我**照抄旧流式代码的反模式**到新写的 `/api/ai/chat`，没意识到它是"长内容必崩"的雷。
- **对策（铁律）**：
  1. **任何 UI 功能交付前，必须在真实浏览器跑一遍核心流程**（打开页 → 触发动作 → 看 Console 有无红色报错 → 确认结果真的渲染出来）。语法/单测通过 ≠ 用户能用。
  2. 新写 SSE/流式端点，默认 `asyncio.Queue()` 无限队列；长文本场景绝不用有界队列（线程生产者不能 await，有界队列必 `QueueFull`）。
  3. 复用已有代码模式前，先问"它踩过坑吗？"——照抄前先查本文档「已知技术坑」章节。

### 错误 8（元规则）：声明"完成"前没有真实验证 —— 本案最该不二过的
- **现象**：导航漏改、nextTick 白屏、QueueFull 白屏等多个错误的共同点是——我都以为"改完测过了"，但验证层不对：要么没 grep、要么没在浏览器跑、要么没 curl 接口。
- **根因**：把"语法通过 / 单测通过"误当成"用户能用"。
- **对策（铁律 · 覆盖一切，优先级最高）**：
  - **前端改动** → 真实浏览器跑核心流程 + 开 Console 看红字。
  - **后端/接口改动** → curl / TestClient 打真实请求，看 HTTP 码 + 返回体 + 后端日志有无异常。
  - **全局改动（导航/样式/组件）** → `grep` 确认所有受影响页面都改到。
  - **数据/数值结论** → 跑脚本逐条输出 delta，不口头臆断。
  - 以上四条，**少一条就不能说"完成"**。

### 错误 9（huntzone 专项）：改函数签名漏 grep 调用点 → 线上 500 + 功能静默降级
- **现象**：把 `huntv2_core.fetch_daily_1d` 返回值从 2 元组升 3 元组 `(rows, err, source)` 后，画廊/每日页方向翻转、用户报"做多"。修方向时又爆 `/api/huntv2/ladder` 500 `ValueError: too many values to unpack (expected 2)`。
- **根因**：改返回值**只改了 `huntback_sim` / `huntzone_gallery_core` 两处**，漏改 `main.py:1347`（`/api/huntv2/ladder`）和 `huntzone_daily_core.py:60`（`_recompute_direction`），外加测试 monkeypatch 仍返回 2 元组。漏改的调用点一个炸 500、一个被 try/except 吞成"无信号"。
- **对策（铁律）**：
  1. 凡改**被多处调用的函数签名**（返回值/参数），动手前先 `grep "函数名" **/*.py` 找出**全部**调用点，列清单逐一改。
  2. 改完 `grep` 数一遍调用点数 == 已改点数，确认全覆盖，再交付。
  3. 测试里若有该函数的 monkeypatch / mock，返回值结构必须同步更新。

### 错误 10（huntzone 专项 · 元根因）：测试环境 ≠ 生产环境 → 本地全绿线上炸
- **现象**：上述 500 修完后，画廊/每日页仍"无信号"。本地 pytest 24 过、py_compile 全过，但用户机器上取数全失败。
- **根因**：我只在**托管 venv**（requests 较新）里验证；用户实际跑 uvicorn 的是**系统 Python `D:\sortware\python_3_10`**（requests 较旧）。两环境行为差导致只在用户侧炸。
- **对策（铁律）**：
  1. 凡依赖第三方库的行为（尤其 requests / 网络 / 编码），**必须用用户实际运行的那套 Python 跑一遍真实调用**，不能只信 pytest/py_compile。
  2. 跨环境交付前，用 `python --version` + `python -c "import requests; print(requests.__version__)"` 对齐两环境的库版本。

### 错误 11（huntzone 专项）：第三方库 API 兼容性 → 取数全失败被静默成"无信号"
- **现象**：`requests.get(url, proxies=..., trust_env=False)` 在旧版 requests 抛 `TypeError: Session.request() got an unexpected keyword argument 'trust_env'`，Twelve Data 与 fapi 双双取数失败，上层把"取数失败"和"真无信号"混为一谈。
- **根因**：`trust_env` 是 **Session 属性**，不是 `requests.get` 的关键字参数；旧版 requests 直接拒收。
- **对策（铁律）**：
  1. **零代理永远用 Session 写法**（跨版本安全）：
     `session = requests.Session(); session.trust_env = False; session.get(url, proxies=PROXIES, timeout=15)`。
  2. **绝不写** `requests.get(url, trust_env=False)`——它只在较新 requests 生效，旧版直接崩。
  3. 取数失败要**显式区分**：API 层 502（取数失败，带 `err`/`source`）vs 200+`ok:False`（真无信号）；把 `source`/`err` 透出响应体，别让真错误被"无信号"掩盖。

## 三、已固化的技术事实（下次直接复用，不重踩）

1. **做空方向判定**（backtest.py 核心）：
   - 做多：`hit_sl = lo<=sl`、`hit_tp = hi>=tp`
   - 做空：`hit_sl = hi>=sl`（SL在上方，用最高价触）、`hit_tp = lo<=tp`（TP在下方，用最低价触）
   - 同根 SL/TP 同时命中 → SL 优先（保守）。

2. **价格对齐校验**（A 修复）：
   - 锚定信号时刻 1m 柱**开盘价**；`delta = db_open − table_entry`
   - `|delta| > 3 pip` → 入场/SL/TP1/TP2 **整组 +delta 平移**，SL/TP 与入场的距离不变（R倍数不变）
   - `|delta| ≤ 3 pip` → 不动，视为已对齐
   - 原值保留在 `orig_entry`，便于核对。

3. **viewWindow 默认 100**（replay.html）。realtime 轮询 2s，同一根 1m K线内不新增蜡烛（只会更新当前根 OHLC）。

4. **AI复盘库**：
   - 存储：`D:\Winner\quant_review\ai_history.json`（本地 JSON，重启不丢）
   - 接口：`GET /api/ai/history`、`DELETE /api/ai/history/{id}`、页面 `/ai_history`
   - 生成成功自动保存；记录含 时间/报告全文/摘要/整体胜率(现算)/总盈亏(现算)/信号表/品种。

5. **回测摘要字段**：`summary` 有 `total_signals / closed_count / open_count / end_equity / total_return / max_drawdown`，**没有整体胜率和总盈亏**——需要的话从 `trades` 现算（closed 笔数里 result 非 SL/未平仓 即赢）。

## 五、承诺

以上 8 类错误（含 2026-08-27 多轮对话双白屏）均已真实发生过。其中**错误 7 + 错误 8 是最让我失望的**——大模型多轮对话功能交付时我连两个白屏 bug 都没在浏览器里发现，只过了语法/单测就把"完成"交给你，这是验证纪律的彻底失守。

下次若再犯同类，视为**未遵守本纪律**：
- 漏改导航 / 时间戳错比价 / 过度实现 / 不先 curl 就改前端 / 手滑误伤代码
- **最不能忍**：写完 UI 不在真实浏览器跑核心流程就报"完成"；复用旧模式不查坑就照抄。
- **huntzone 新增三条红线**：
  - 改被多处调用的函数签名，不先 `grep` 全调用点就动手（→ 错误 9 线上 500）。
  - 只在托管 venv 验证、不拿用户实际运行的 Python 跑真实调用就报"完成"（→ 错误 10）。
  - 写 `requests.get(..., trust_env=False)` 这种跨版本不兼容的写法（→ 错误 11 取数全失败）。

开工前先读本文件，对照「铁律」逐条自检；每轮对话结束自动沉淀新坑（流程纪律 〇）。
