## 1. 背景与目标

现有 `replay.html` 已能实现「K 线回放 + 检查点卡点暂停 + 回车继续」。现在需要新增一套**信号复盘回测**能力：把你在交易日志里记录的每笔信号（形态/架构、方向、入场、止损、止盈）导入系统，用 1 分钟 K 线数据**客观验证每笔信号最终打到止损还是止盈**，并进一步做**策略层面的盈亏比统计、资金曲线推演**。

目标产出：
1. 导入信号表（CSV / 粘贴） → 自动回测 → 标注每笔结果（SL / TP1 / TP2 / 未触发）。
2. 按「形态/架构」分组，统计胜率、盈亏比、期望值、最大连亏，并给出**该策略历史最优盈亏比建议**。
3. 资金曲线：200u 起步、0.01 手固定、7:00–23:00 交易、点差成本，输出净值曲线与关键指标。
4. （可选）K 线图上叠加信号标记 + 暂停时显示信号详情。
5. （可选）阿里云百炼（通义千问）生成自然语言复盘报告。

## 3. 数据模型

### 3.1 信号表字段（导入）
| 字段 | 类型 | 说明 |
|------|------|------|
| 信号时间 | datetime | `YYYY/MM/DD HH:MM`（兼容当前斜杠格式） |
| K线周期 | string | 1m/5m/15m/30m/4h，仅展示与归类用 |
| 形态/架构 | string | 策略分组键（如 `EMA100+HA回调`、`看跌Pinbar`） |
| 方向 | string | 做多 / 做空 |
| 入场价 | float | entry |
| 止损价 | float | SL（可为空，则无法判亏） |
| 止盈TP1 | float | TP1（可为 `-` 空） |
| 止盈TP2 | float | TP2（可为 `-` 空） |

支持两种导入方式：① 粘贴多行文本（TSV/逗号自动识别）；② 上传 `.csv` 文件。
字段缺失/无法解析的行标记为「跳过」并在结果里列出。

### 3.2 行情数据
复用现有 `/api/kline/review`，取 **1m** 数据。
- 每条信号按「信号时间 − 若干根」到「当天 23:00 / 数据末」拉取对应 1m 序列。
- 为提高效率：后端一次性拉取「当日 7:00 → 23:00」全量 1m（最多 960 根/天），前端/后端按信号时间切片，避免每条信号重复请求。

## 4. 回测引擎（核心算法）

### 4.1 触发判定（逐根扫描）
对单笔信号（dir, entry, sl, tp1, tp2），从信号时间**之后第一根** 1m 开始，到 23:00 为止：

- **做多 long**：盈利看 price↑，亏损看 price↓。
  - 触及 TP：`high >= tp`；触及 SL：`low <= sl`
- **做空 short**：盈利看 price↓，亏损看 price↑。
  - 触及 TP：`low <= tp`；触及 SL：`high >= sl`

扫描每一根 1m K 线，按优先级判定：
1. 若本根内 **SL 与 TP 同时被穿越**（即 high 够到 TP 且 low 够到 SL）→ 触发「同根冲突」，按**保守原则默认 SL 先到**（对交易者不利但最稳健，可配置切换为「按开盘方向」）。
2. 否则按谁先穿越谁生效。

### 4.2 TP1 / TP2 处理（待确认，见 §11）
提供两种模式（PRD 默认采用模式 A）：
- **模式 A（不分仓）**：以「先到 SL 还是先到 TP2」定胜负；TP1 仅作为观察标记记录「是否触及 TP1」。最终盈亏 = 到 TP2 盈利 / 到 SL 亏损。
- **模式 B（分仓）**：TP1 平 50% 仓位并移保本，剩余 50% 看 TP2；TP2 到则再盈利，回撤到成本则保本离场。

### 4.3 未平仓与跨日处理（已确认）

- 每笔信号从信号时间起持续向后扫描 1m，直到触及 SL/TP **或** 到达回测截止时间。
- **每日 23:00 快照**：若当日 23:00 仍未了结 → 标记【未平仓】，按当日 23:00 收盘价计算浮动盈亏，计入资金曲线；该单**不计入**策略胜率 / 盈亏比 / R 期望统计（仅统计已完全了结的交易）。
- 未平仓单次日继续运行，下个交易日的 23:00 重新用新收盘价更新浮盈浮亏（资金曲线每日带上浮动盈亏；统计仍只算已了结）。
- 到达回测截止时间仍未了结 → 按截止时刻收盘价结算并标记【未平仓-截止】。
- 回测数据范围：拉取「最早信号日 7:00 → 回测截止日 23:00」的全量 1m（回测截止日默认 = 信号最晚日 + 1 天，可配）。

### 4.4 结果字段
每笔输出：`信号时间, 策略, 方向, 入场, SL, TP1, TP2, 结果(SL/TP1/TP2/持有), 触发时间, 触发价, 盈亏(u), R倍数, 备注`

## 5. 策略统计分析

按「形态/架构」分组（如 `EMA100+HA回调`、`看跌Pinbar`、`黄金孕线`、`BSG+SFP`…）：

| 指标 | 含义 |
|------|------|
| 信号数 N | 该策略出现次数 |
| 胜率 | 盈利笔数 / 有效笔数 |
| 平均 RR | 平均 (TP距离 / SL距离)，分 RR1（对TP1）、RR2（对TP2） |
| 期望值 EV(R) | 胜率×平均盈利R − 败率×平均亏损R |
| 最大连亏 | 连续亏损最大笔数 |
| 盈利因子 | 总盈利 / 总亏损 |

### 5.1 最优盈亏比扫描（重点需求）
对每个策略，固定 SL 不变，**扫描 TP 倍数 k ∈ {1.0, 1.5, 2.0, 2.5, 3.0, 4.0}**（TP = entry ± k×|entry−SL|），重新回测该策略全部信号，计算各 k 下的期望值 EV(k)。取 **EV(k) 最大** 的 k 作为「该策略建议盈亏比」，并输出扫描曲线图。

> 这直接回答你「每个策略盈亏比设置多少比较好」。

## 6. 资金与风控模型

- 起始资金：**200 u**
- 固定手数：**0.01 手**（：1 美金波动 = 1 u，已确认）
- 交易窗口：**每日 7:00 – 23:00**（窗口外信号不计入资金序列；或标记跳过）
- 点差成本：**单边开仓 0.3 u/笔**（用户确认：点差仅开仓瞬间收取，平仓不再扣；30 pips = 0.30 美金/手 × 0.01 手 = 0.3 u，**不得双边乘 2**）。
- 佣金手续费：多数平台双边（开/平各扣），本期不接入；若后续加，需单独从盈亏扣除，与点差分列。
- 结算：按 §4 每笔盈亏(u) 累加，绘制**净值曲线**（按信号时间顺序）。
- 风控提示：固定手数下若单笔 SL 距离较大（如 30 u × 3 = 90 u），连亏 3 笔即穿仓 > 200 u。PRD 建议输出「最大回撤、是否穿仓、穿仓笔数」并提示是否需要引入「本金不足暂停」规则（可配置）。

输出：净值曲线图 + 关键指标（终值、总收益率、最大回撤、 Sharpe 简易版、穿仓次数）。

## 8. 大模型（阿里云百炼）接入（本期不接入，下一期）

> 用户确认：本期先交付纯数值回测与统计报表（填充每笔盈利情况），AI 复盘留到下一期，基于本表结果再调用大模型分析。

**结论：核心回测与统计不需要大模型。** 胜负判定、RR、资金曲线、最优 k 扫描全是确定性数值计算，纯 Python 即可，引入大模型反而增加延迟与不确定性。

**大模型适合做什么**：在以上计算结果出来后，生成一份**自然语言复盘报告**——例如「EMA100+HA回调 在 7–9 点震荡段胜率 72%，但 14 点后趋势段被连续止损，建议缩小 SL 或避开单边行情；BSG+SFP 组合在 1m/15m 共振时 EV 最高」。

- 后端新增 `POST /api/ai/summary`，把「策略统计 JSON」发给阿里云百炼（通义千问 qwen 系列，用户已有账号），返回文本。
- 前端加「生成 AI 复盘」按钮，默认**关闭**，勾选才调用，避免无谓消耗。

## 11. 关键决策点（已确认记录）

以下问题已在 2026-08-25 由用户拍板，作为开发口径：

1. **点差「30」**：30 pips = 0.30 美金/手；0.01 手下单笔成本 = **0.3 u**，开仓即计。
2. **TP1/TP2 分仓**：采用**模式 B**——TP1 平 50% 并移保本，剩余 50% 看 TP2；回撤到成本保本离场。
3. **阿里云百炼**：本期**不接入**，下一期基于本表结果再调大模型生成复盘。
4. **K 线叠加**：本期**不做**，下一期评估方案 X / Y。
5. **点差口径**：单边开仓 0.3u/笔，平仓不再扣；佣金手续费本期不接（后续单独列）。
6. **未平仓跨日**：每日 23:00 快照按收盘价算浮动盈亏计入资金曲线，标记【未平仓】，不计入胜率/盈亏比/R 统计；次日继续运行，下个 23:00 重算。

## 12. 风险与注意

- 1m 数据同根内 SL/TP 同时穿越时无法精确到秒，采用保守（SL 优先）原则，可能略低估胜率。
- 固定 0.01 手 + 200u 起步，大止损策略可能穿仓，资金曲线会显示负净值，需明确是否引入暂停规则。
- 信号时间若落在非交易时段（如 23 点后）或数据缺失区间，该笔标记为「无法回测」。
- 所有回测严格因果：只用信号时间**之后**的 K 线，杜绝未来函数。
